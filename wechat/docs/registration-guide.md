# 配置自己的微信体验工程

本指南面向新使用者的独立环境。公开源码仅包含占位配置，不包含原用户的 AppID、云环境、管理员身份或历史验收附件。此前个人开发版本的状态见 [工程状态](engineering-status.md)，不能将其当作本副本已部署。

## 可直接用于注册的资料草案

| 项目 | 准备内容 |
| --- | --- |
| 账号类型 | 正式微信小程序，不能使用接口测试号代替 |
| 首选名称 | 家人血糖本（以平台实际可用结果为准） |
| 名称备选 | 爸妈血糖本、每日血糖随记 |
| 简介 | 记录每次血糖，回看近期变化。支持手动输入、拍照识别后核对保存，各自微信独立记录。 |
| 实际功能 | 本人测量记录、历史回看、7/30 天趋势、自设范围、拍照数字识别、本人云端保存、字号设置、导出和删除恢复；暂不共享 |
| 登录资料 | 用微信在该小程序中的身份标识区分用户；不需要手机号、昵称、头像、位置或通讯录 |
| 图片用途 | 用户主动拍照或选图后，经专用云端识别服务读取数字；本人核对后保存读数，原图不随记录长期保存 |
| 记录数据 | 血糖读数/单位、测量日期和时机、餐后间隔、选填备注、个人范围和显示偏好 |
| 管理员 | 可继续使用本人现有微信；记账小程序及其体验版本保留 |
| 必须本人填写或确认 | 注册邮箱及验证、真实主体资料、平台实际允许的类目、实名/扫码、隐私指引及平台条款；不能由工程虚构 |

当前浏览器安全策略禁止代理访问微信公众平台，不能代填或提交注册，也不能通过其他浏览器/接口规避。账号持有人在平台完成注册后，只需提供公开 AppID；有已关联云环境时也可提供环境 ID。不需要 AppSecret、密码、验证码或私钥。截图中若意外展示密钥，应由账号持有人在后台重置，不将密钥写入本工程。

## 1. 注册并确认账号能承载实际功能

可使用用户明确指定、确认供本项目使用的闲置小程序账号；不需要新注册微信号。先取得名称和 AppID，核对是否与正在使用的记账小程序相同，保留其代码、体验版本和数据。若无可用账号，再在 [微信公众平台](https://mp.weixin.qq.com/) 注册小程序，按真实主体资料选择符合条件的个人主体。管理员通过微信完成平台所需实名、扫码和账号验证。不要把血糖工程上传到仍在使用的记账 AppID。

实际功能是：本人记录血糖、设置自己的目标范围、查看描述性变化、拍照识别后核对、自己的微信账号云端保存；暂不共享，不提供诊断、处方、问诊或医疗器械销售。先在真实账号后台核对当前可选服务类目、各类目主体限制和资质要求。**本项目没有可靠核实个人主体可选的具体类目，不代选类目、不保证某类目一定允许，也不建议为过审隐瞒健康记录功能。** 如后台没有符合实际功能的个人主体类目，需要由账号持有人根据平台要求决定主体或功能范围，代码工作可以保留。

填写名称、简介、图标与实际功能一致的资料。在隐私保护指引中按真实流程说明微信身份标识、血糖读数、单位、测量时间/时机、备注、个人目标和显示偏好，分别用于账号识别、本人记录、同步和分析。头像、昵称、手机号、位置、通讯录不是本版所需权限，不必为登录申请。

拍照/相册用于读取血糖仪照片；照片识别结果必须核对后保存。若启用生产 OCR，照片经微信云函数传往自己配置的 HTTPS OCR 容器，在内存中处理，不随记录长期保存。应按真实服务商、处理链路和平台后台可选字段填写隐私指引，核对容器平台日志策略；不能写成“仅在手机上识别”。如暂不启用，保留拍照对照手动填写和单独手动输入。

平台类目、隐私审核、协议和费用均以当前账号后台为准；由账号持有人阅读并确认。本工程脚本不接受平台条款、不完成实名认证、不购买服务。

已有闲置账号也需确认能使用云开发。仅有 `wx` 开头 AppID、AppSecret 或能进入开发者工具，不能证明它是可使用云服务的正式小程序。遇到 `-601059` 时先核对账号类型，而不是借用正在使用的记账 AppID 或填造云环境。

## 2. 取得两个公开配置值

1. 在该小程序的开发设置中取得 **AppID**，形如 `wx` 加 16 位十六进制字符。
2. 安装并打开微信开发者工具，由拥有此 AppID 开发权限的微信正常扫码登录。导入 `wechat/` 目录，选择真实 AppID。
3. 打开该小程序的云开发入口，核实账号可用的环境、套餐、配额、超额计费、试用截止和欠费策略，再由账号持有人决定是否创建/启用。**不默认承诺免费，也不自动创建付费环境。** 环境须关联本小程序；取得环境 ID。
4. 在工程执行：

```sh
cd /path/to/glucose-tracker/wechat
npm ci
npm --prefix cloudfunctions/glucose ci --ignore-scripts
npm --prefix cloudfunctions/recognize ci --ignore-scripts
npm run configure -- --appid wx替换为真实16位标识 --env 替换为真实云环境ID
npm run ready
```

示例文字不是可执行的真实 ID。AppID 与环境 ID 都是公开标识，不是密码；不需要把 AppSecret、微信登录二维码、上传私钥或 OCR token 发到聊天、放入小程序或 Git。`configure` 校验参数并保留既有公开配置，只写 `project.config.json` 与已忽略的 `miniprogram/config.local.js`；写入失败尝试恢复原配置，不会登录或开通服务。`ready` 校验两个 ID 的格式及工程配置，损坏的本地配置会阻止部署和上传；这些本地检查不能替代账号权限与环境关联验证。

## 3. 手工建立隔离数据库

在所选云环境的数据库控制台创建：

| 集合 | 保存内容 | 客户端权限 |
| --- | --- | --- |
| `glucose_accounts` | 个人目标、显示偏好、同步版本 | 仅管理端可读写 |
| `glucose_records` | 个人测量记录、删除状态 | 仅管理端可读写 |
| `glucose_operations` | 幂等操作回执 | 仅管理端可读写 |

分别设置安全规则为 `{ "read": false, "write": false }`；规格在 [database.rules.json](../cloudfunctions/glucose/database.rules.json)。该文件以集合名分组，**不是可直接整体粘到单个集合中的规则**。按当前控制台逐个集合应用并保存，不覆盖其他项目的规则或数据。

在 `glucose_records` 上建立唯一复合索引 `owner_sync_version`：`ownerKey` 升序、`syncVersion` 升序；核对 [database.indexes.json](../cloudfunctions/glucose/database.indexes.json)，等控制台显示索引可用。主键读取使用默认索引。`deploy` 不会建集合、改规则或创建索引。

所有个人读写只经 `glucose` 云函数，可信身份来自云端 `getWXContext()`；客户端不能传一个 openid 来切换数据归属。即使规则拒绝客户端，云函数仍有管理端权限，服务端归属校验必须保留。管理员具有技术管理能力，本版不宣称端到端加密。细节见 [云端安全说明](cloud-security.md)。

## 4. 部署云函数，核对实际依赖

入口为 `index.main`，使用微信事件调用，不创建匿名 HTTP 触发器。当前微信开发者工具默认创建 Node.js 16.13 函数，本工程发布包已针对这一平台实际版本编译；通过完整 CloudBase 控制台新建时，可优先选择平台支持的较新 Node.js 运行环境。实际版本须从云端配置核对，不能把包中的 engines 字段当成运行时已升级。[CloudBase 运行环境支持](https://docs.cloudbase.net/cloud-function/runtime-support)。`glucose` 已设置 `GLUCOSE_ALLOWED_APP_ID` 为本项目公开 AppID。

部署后在控制台核对实际超时设置：`glucose` 使用 20 秒，`recognize` 至少 20 秒，以覆盖 OCR 桥接的 15 秒整体请求时限和函数启动开销。CloudBase 文档列出的普通事件函数默认超时为 3 秒，不能直接依赖默认值。本工程的 `config.json` 只声明 API 权限，没有声称已修改云函数运行参数。[CloudBase 官方基础配置](https://docs.cloudbase.net/cloud-function/function-configuration/config)

```sh
npm run deploy
```

脚本先执行 `ready`，缺配置立即停止；随后用本机 npm >= 8.3.0 执行云函数 `npm ci --ignore-scripts`、校验限定 overrides 的实际版本、运行后端测试，再将业务代码和依赖打包为独立 CommonJS 文件。官方 CLI 使用明确 AppID、环境 ID 和临时发布目录部署；发布清单含锁文件、输入源码和输出文件的 SHA-256，保存在 `artifacts/cloud-deployment-manifest.json`。**不使用远端 npm 安装。** 当前工具直接上传 node_modules 目录时实际返回 EISDIR，独立文件包已被同一工具接受。临时包结束后清理，原始源码和锁定依赖不改写。脚本不自动扫码登录、开通环境、修改数据库或购买服务。

`glucose` 固定 wx-server-sdk 4.0.2，并通过限定 overrides 维护 Axios 0.34.0 / lodash.unset 4.18.0；这些本机已验证的实现随独立文件包上传。发布包只有 index.js、config.json、无 dependencies 的 package.json，不会在云端重新解析依赖。手工对原始函数目录选择“云端安装依赖”会改变这一发布方式，不能只凭本地 lockfile 断言远端支持 overrides；须核实安装器和最终版本，否则按本工程脚本重新部署。CLI 成功回执后仍要核对目标环境、实际运行配置与微信调用结果。

SDK 仍包含上游未修补的 lodash.set 原型污染依赖路径；当前服务没有调用已识别的 watch/任意字段路径更新路径，不能称依赖风险清零。查看 [依赖审计及实际调用边界](cloud-security.md#已修复的依赖与剩余审计项) 与 [dependency-audit.json](../cloudfunctions/glucose/dependency-audit.json)。

可选 OCR 桥接部署命令：

```sh
npm run deploy -- --with-ocr
```

这只会在部署 `glucose` 的同时部署 `recognize` 事件云函数。HTTPS OCR 容器、资源费用、`OCR_URL`、随机 `OCR_TOKEN` 与可选 `EXPECTED_APPID` 仍需账号持有人按 [生产 OCR 接入](production-ocr.md) 配置；token 只放云函数和容器服务端。没有配置时返回 `OCR_NOT_CONFIGURED`，拍照后仍可对照手动填写。脚本不上传容器镜像或自动购买 OCR。

`recognize` 也锁定相同 SDK 与限定维护依赖；它使用 SDK 初始化和可信微信上下文，不调用数据库或 watch。上游 SDK 依赖树仍包含上述未修补路径，不能把本函数未调用 watch 写成依赖漏洞已经修复。

## 5. 两个真实微信账号验收

先在开发者工具与真机调试中完成云调用；测试账号须按工具和平台要求具备相应项目权限。以下两账号验收由两个不同微信身份完成，不能用前端切换人物或改请求字段代替。

| 场景 | 应看到的结果 |
| --- | --- |
| 父亲账号 A 首次进入 | 本人空记录；示例入口明确隔离，无示例上传 |
| A 保存、重开小程序 | 云端确认才显示已同步，重开后仍有本人记录 |
| 母亲账号 B 首次进入 | 看不到 A 的读数、目标、备注、删除记录或本机队列 |
| B 写入不同数值/目标 | B 仅见自己的数据，A 的数据不变 |
| 验证身份前/同机切换微信 | 不展示上个账号缓存；待上传队列不串到新账号 |
| 请求伪造 owner/openid、他人记录编号 | 字段被拒绝或只影响本人同编号记录；不返回他人内容 |
| 客户端直接读写集合 | 被数据库规则拒绝 |
| 断网新增后重开、再联网 | 明确待同步；重传后只有一条，不冒充已保存云端 |
| 同一账号两设备改同条记录 | 显示冲突，保留本人本地未上传内容供核对 |
| 删除、恢复并在另一设备刷新 | 状态一致；不因旧缓存把删除项错误复活 |
| 换新设备登录本人微信 | 联网取回该账号已上传记录、个人目标与偏好 |
| OCR 未配置/失败/数字模糊 | 说明状态，可手动输入；不编造样例读数、不自动保存 |

同时检查大字模式、两种录入、单位、测量时间、图表与无目标时的分析文案。目标是本人设置的比较范围，不将自设范围包装成医生建议。用真机核对拍照隐私授权、安全区、键盘和断网体验。

## 6. 上传并设为体验版

先完成以上云端验收，再明确运行上传命令：

```sh
npm run upload -- --version 0.1.0 --desc "家人血糖本：个人记录与云端保存"
```

只有显式执行 `upload` 才上传代码。脚本先 `ready`，再 build/check/test，通过后调用官方 CLI；不会自动部署云函数、修改规则、登录、购买或送审发布。开发者工具服务端口若关闭，需要账号持有人在工具正常设置里启用；不要绕过权限。

在 [微信公众平台](https://mp.weixin.qq.com/) 的版本管理中核对刚上传的版本，设为体验版；再按后台流程添加父母微信为体验成员。让父母各自扫码打开，重新验收本人身份、保存和重开恢复。CLI 的临时 preview 二维码与后台设定的体验版不同，不能互相替代。普通正式发布/送审不属于该上传脚本自动动作，仍按平台真实要求办理。

保存版本号、部署时间、AppID/环境关联、规则/索引截图和两账号验收结果，截图不要包含读数或完整身份。长期使用前另做云数据库备份策略及恢复验证；云保存不等于已完成独立备份，未上传的离线记录不能从云端恢复。
